# AGENTS.md

This file gives Codex repo-specific guidance for working on The Hypertextual
Library.

## Project Overview

The Hypertextual Library is a static site for reading public-domain texts
hypertextually. On a work page, every rendered word is clickable: clicking a
word searches the full text for other occurrences, while Alt+click attempts a
dictionary lookup.

The site is intended for GitHub Pages and is configured with `CNAME` for
`hypertextlibrary.com`.

## Current Tooling

Use Python 3 explicitly on this machine:

```bash
python3 utils/generator.py
```

There is no repo-root `generator.py`, and `python` is not available in the
current local environment. The generator expects to be run from the repo root
because it opens paths like `template/template.html` and `data.json`.

There is no package manager setup, build manifest, linter, formatter, or test
suite yet. For local browser testing, serve the repo root as static files, for
example:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/`.

## Source Of Truth

- `data.json` is the source of truth for book metadata.
- `template/template.html` is the template for each generated work page.
- `template/library.html` is the template for root `index.html`.
- `template/raw_text.js` wraps each work's raw text into a `raw_text` global.
- `books/<uniquename>/text.txt` is the source text for books.
- `books/<uniquename>/cover.jpg` is the source cover image copied into the
  generated clean-URL reader folder.

The main hand-authored runtime files are:

- `js/book-page-search.js` for work-page pagination, chapter navigation, search,
  result rendering, highlighting, theme toggling, and dictionary lookup.
- `js/index.js` for library-page filtering and theme toggling.
- `js/multithread.js` is a legacy Web Worker helper and is not loaded by the
  current templates.
- `js/dictionary.js` for the bundled dictionary object.
- `css/light.css` and `css/dark.css` for the two themes.
- `index.html` and `placeholder.html` are hand-authored static pages, not
  generated by the current generator.

## Generated Files

Running `python3 utils/generator.py` rewrites:

- `books/index.html`
- `js/books.js`
- `index.html`
- `<uniquename>/index.html`
- `<uniquename>/raw_text.js`
- `<uniquename>/cover.jpg`

Prefer editing `data.json`, `template/`, source text files, shared JS, or shared
CSS, then regenerate. Avoid hand-editing generated files unless the task is
explicitly about preserving or inspecting generated output.

## Adding A Book

1. Add an entry to `data.json` under `books` with `title`, `author`, and
   `uniquename`.
2. Create `books/<uniquename>/`.
3. Format source text from a public-domain source and save it as
   `books/<uniquename>/text.txt`.
4. Chapter headings should use this exact shape:

   ```text
   -------- Chapter Title --------
   ```

5. Keep lines roughly 75 characters or shorter for the current reader layout.
6. Add a cover image at `books/<uniquename>/cover.jpg`.
7. Run `python3 utils/generator.py` from the repo root.
8. Inspect the generated page in a browser and check that search, chapter
   navigation, pagination, and cover loading still work.

## Runtime Architecture

Each generated work page loads `raw_text.js`, which defines one global variable:
`raw_text`. `js/book-page-search.js` then:

- Splits the text into lines.
- Pads chapter breaks so chapters start on new 35-line pages.
- Builds a chapter dropdown from lines containing `--------`.
- Renders each page into clickable word anchors.
- Searches the full text and renders matching lines in the results table.
- Highlights searched terms on the current page and in result snippets.
- Uses `js/dictionary.js` for the unfinished Alt+click dictionary feature.

The books library page loads `js/books.js`, which defines a global `book_list`
containing generated metadata plus prebuilt HTML snippets. `js/index.js` filters
that list as the user types.

## Known Revival Notes

- `js/book-page-search.js` now builds reader and result content mostly through
  DOM APIs. Keep escaping in mind if adding user-uploaded texts or broader
  content sources.
- Some candidate texts may not be public domain in every jurisdiction. Recheck
  copyright status before adding or redeploying texts publicly.

## Verification Checklist

For documentation-only changes, check `git diff` and `git status --short`.

For generator, template, metadata, text, or cover changes:

```bash
python3 utils/generator.py
git status --short
```

Then serve locally and inspect at least:

- `/`
- one generated book page, such as `/alice/`

On work pages, verify initial render, next/previous pagination, chapter dropdown,
manual search, click-to-search, highlighting, and light/dark toggle.
